## CSV import

Settings → Data → Import Transactions offers a shareable CSV template and the system document picker. The template has exactly these columns:

```csv
Date,Type,Amount,Description,Category,Account
2026-10-01,Expense,1.00,,Coffee,Cash
2026-10-01,Expense,8.50,Weekly shop,Groceries,Cash
2026-10-01,Expense,30.00,,Fuel,Card
2026-10-01,Income,50.00,Client payment,Client Payment,Bank
```

Headers may be reordered and are case-insensitive. All six headers are required, but Description values may be blank. Date uses a valid YYYY-MM-DD calendar date; Type is Expense or Income, case-insensitive. Amount must be positive EUR with at most two decimal places and is converted to integer cents exactly. A comma decimal value must be CSV-quoted. Standard quoted commas, escaped quotes, multiline descriptions and UTF-8 text are supported. Line endings are normalized to LF; error row numbers identify logical CSV records, including the header, rather than physical lines inside quoted fields.

Selecting a file only parses and previews it. No finance writes occur before confirmation. Invalid rows show their fields and problems; confirmation explicitly states how many will be skipped. Unknown account names require mapping to an existing active account. Accounts are never created automatically. Category names resolve case-insensitively to compatible active categories; archived, incompatible or ambiguous references are rejected. New categories require explicit approval, with expense/income/both derived from their valid rows. Blank descriptions use the resolved category name.

Confirmation revalidates the preview and commits all selected transactions, approved categories and import history in one SQLite transaction. Errors or lock interruption roll back the whole import. Each entry receives a normal UUID and pending sync status. One post-commit invalidation triggers the existing sync flow; repeated cloud sync uses those UUIDs. Account initial balances are never changed. Imported entries add their normal income/expense effects to balances and dated reports.

Migration 6 adds only local `import_batches` metadata and an index; migrations 1–5 and existing money records are preserved. SHA-256 content fingerprints warn about previously imported content on this device, with Cancel or explicit Import Anyway. Legitimate identical transaction rows are preserved. BOM differences are ignored by the fingerprint; changed line endings or edited content produce a different fingerprint. Import history is not cloud-synced or restored onto a new phone, so duplicate-file warnings do not span devices.

Limits: UTF-8 `.csv`, 5 MB, 10,000 records and at most 100 newly approved categories per import. Parsing uses bounded in-memory input; insertion yields and reports progress every 100 rows. The picker may leave its copy in private OS cache. Template sharing uses the existing private-cache file and native share path. Existing extended CSV exports and JSON backups are not this six-column import format; JSON remains export-only.
